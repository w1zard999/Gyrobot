# Дизайн: управление WASD по Bluetooth (HC-05 + ПК-клиент)

Дата: 2026-09-21. Статус: утверждён пользователем.
Робот: Nano + MPU-6050 + TB6612, прошивка `firmware/gyrobot_mov` (порт
listing_PID_2I_mov + энкодерный/курсовой контуры, живые параметры по сериалу).

## Цель

Езда вперёд/назад и повороты с клавиатуры ПК: WASD по Bluetooth, робот при этом
всегда балансирует. Телефон отпадает: iPhone не умеет BT-serial с HC-05.

## Железо и подключение

- HC-05 на штатное место D0/D1 (аппаратный UART, общий с USB-чипом).
  TX модуля → D0 (RX), RX модуля → D1 (TX) через делитель 1к/2к (у HC-05 вход 3.3 В).
- Разовая настройка модуля: AT-режим, `AT+UART=115200,0,0` — прошивка живёт на 115200.
- Windows: спарить (PIN 1234/0000), взять исходящий «Standard Serial over Bluetooth» COM.
- Правила сосуществования: во время езды USB не втыкать; для прошивки модуль
  обесточивать (его TX на D0 мешает загрузчику).

## Модель управления (подход «наклоном равновесия»)

- **W/S** — целевой наклон `±drv` (живой параметр, старт 2.5°, знак задаёт
  направление: если «вперёд» окажется назад — `drv -2.5`). Реальный наклон
  `drvNow` ползёт к цели с TAU 0.3 с (ступенька = качели, урок v4). Наклон
  складывается с нулём равновесия в фильтре угла: баланс работает всегда.
- **A/D** — целевой дифференциал `±trn` (старт 35 ШИМ), сглаживание тем же TAU.
  В `drive()`: левому мотору `+trnNow`, правому `−trnNow`, поверх всего.
- **Комбинации** складываются: W+A = дуга влево.
- **Конфликт с курс-холдом:** пока trnTarget ≠ 0, память курса yawInt угасает
  (×0.9 за окно) — контур курса не воюет с водителем; отпустил — держит новый курс.

## Протокол и watchdog

- Клиент при удержании шлёт буквы ~10 Гц. Каждая буква продлевает
  `cmdDeadline = millis() + 300`.
- Букв нет 300 мс → `drvTarget = trnTarget = 0` (сглаженные значения доезжают —
  робот останавливается плавно и стоит). BT отвалился = то же самое.
- Буквы идут тем же парсером строк, что и настройка: `w` — валидная строка,
  конфликтов с `kp 0.5` нет. Работает и с USB-терминала.
- Падение (armed=false) → цели и сглаженные значения сбрасываются: после взвода
  робот сам не уедет.

## Правки прошивки (текущие файлы)

- Состояние: `drvTarget/drvNow/trnTarget/trnNow/cmdDeadline`.
- `paramsPoll()`: буквы w/s/a/d → цели + продление дедлайна.
- В `loop()`: сглаживание `now += (target − now)·(dt/0.3)`; истёк дедлайн → цели 0.
- Фильтр угла: `accAngle() + balancing_zerro + drvNow` (одна строка).
- `drive()`: к дифференциалу добавляется `(int)trnNow` (кап ±50 вместе с yawTerm).
- В speedTick: при trnTarget ≠ 0 — угасание yawInt.
- Телеметрия: поле `d=` = drvNow (робот «слышит» команды).
- Живые параметры: `drv` (−10..10, знак = направление), `trn` (−100..100).
- Память: <100 байт, флеш: <1 КБ. Запас есть (14.3 КБ / 646 Б на старте работ).

## ПК-клиент `tools/wasd.py`

- Python 3: `pynput` (глобальный слушатель клавиш) + `pyserial`.
- Запуск: `python tools/wasd.py --port COM8` (исходящий BT COM из диспетчера устройств).
- Тик 10 Гц: отправить буквы всех зажатых клавиш WASD (каждая с `\n`).
  Отпущена — не шлётся. ESC — выход. Ошибки порта — сообщение и выход.
- Зависимости: `pip install pynput pyserial` (pyserial уже стоит для talk.py).

## Тест-план

1. Стол, колёса в воздухе: буквы доходят (`d=` меняется), отпускание → `d=` к 0.
2. Пол, `drv 1.5`: направление вперёд (перепутано → `drv -1.5`), остановка.
3. `drv 2.5`: разгон/торможение, A/D на месте и по дуге, толчки в движении.
4. Watchdog: вырубить клиент на ходу → робот останавливается.
5. Откат: `drv 0`/`trn 0` — робот игнорирует BT (чистый баланс).
