## Текущее состояние (залито в плату, коммит 5459191+)

Прошивка: `firmware/gyrobot_mov` — стабильная база (0f76ab2) + WASD-порт
c_movement из оригинального листинга (listing_PID_2I_mov).

- **Стояние**: работает. zr=1.6 (зашит, подобран бисекцией по полу), гуляющий
  ноль оставлен как есть (пользователь принял лёгкий дрейф).
- **Повороты A/D**: работают (mtrn=40, плавный фейд по |pid|/0.7).
- **Езда W/S: НЕ ПРОВЕРЕНА.** Только что залит «фазовый гейт»: рывок
  moveRaw(±mfwd) даётся только в фазе качки `rate >= 0` (вперёд) /
  `rate < 0` (назад), в чужой фазе моторы держат ход. **Знак фазы не
  проверен** — если W/S дрожат как раньше, первой правкой развернуть:
  `bool phaseFwd = (rate < 0);` в gyrobot_mov.ino (шаг 1).
- mfwd=50, mtrn=40 (живые параметры; 200 было — трясло, 50 — не проверено
  с фазовым гейтом).

## Управление

- Клиент: `tools/wasd.bat` (двойной клик) → `tools/wasd.py`, WASD по
  виртуальным кодам (раскладка не важна), шлёт буквы 10 Гц, ESC — стоп.
- BT: HC-05 на D0/D1, 115200, исходящий порт Windows **COM13** (COM12 —
  входящий, COM6/7 — чужой BrainLink).
- USB и BT сосуществуют (слушать по USB можно во время езды по BT).
- **Прошивка: сначала вынуть HC-05 из разъёма** (его TX на D0 глушит
  загрузчик), залить, вставить. COM10 иногда «висит» — передёрнуть USB.

## Почему дрожала езда (разобрано)

Двигаться балансирующему роботу мешает его же баланс: W даёт +50 на оба
колеса, корпус заваливается назад, баланс (порог 0.7) бьёт колёсами назад,
потом вперёд — рубильник ±50 = дрожь. Оригинал лечил фазовым гейтом по
гироскопу (рывок только в фазе наклона вперёд) — этот механизм сейчас в
прошивке и ждёт проверки. Второй рычаг — величина mfwd (200 было много,
у оригинала моторы слабые и мёртвая зона 100).
