# Гиробот

Двухколёсный балансирующий робот на Arduino Nano. Стоит сам, ездит и
поворачивает по командам с клавиатуры через Bluetooth.

Прошивка — `firmware/gyrobot_tumbller`, по схеме Elegoo Tumbller: PD по углу,
PI по скорости и положению колёс (энкодеры), поворот по скоростям колёс.
Почему именно она: `docs/research/`.

## Быстрый старт

1. Включить питание робота.
2. **Положить робота на бок и не трогать.** Гироскоп прогревается и
   калибруется примерно 15–20 секунд. Когда калибровка готова, **колёса
   коротко дёрнутся вперёд**. До этого робот не встанет, даже если его поставить.
3. Поставить робота на колёса вертикально и придержать полсекунды — он начнёт
   балансировать сам.
4. Запустить клиент из корня проекта:
   - Windows — двойной клик по **`wasd.bat`**
   - macOS — двойной клик по **`wasd.command`**
   - Linux — `./wasd.sh`

   Клиент сам найдёт робота среди Bluetooth-портов (первый раз — до 20 секунд,
   дальше помнит порт) и откроет окно управления. **Клавиши работают, пока окно
   в фокусе**; ушёл в другое окно — робот останавливается.

| Клавиша | Действие |
|---|---|
| W / S или ↑ / ↓ | ехать вперёд / назад (пока зажата) |
| A / D или ← / → | поворот влево / вправо на месте |
| W+A и т.п. | езда с поворотом |
| H | вернуться домой (по прямой, в конце встать в исходное направление) |
| R | дом здесь: текущие место и направление становятся домом, след стирается |
| C | стереть след на карте |
| ESC или закрыть окно | выйти из клиента (робот остановится и будет стоять) |

Раскладка клавиатуры не важна. В окне видно связь, нажатые клавиши, наклон,
скорость и поворот. Отпустил клавишу — робот плавно тормозит и
держит место. Упал — положить его или поставить заново: встанет сам.

## Железо

- Arduino Nano (ATmega328P), MPU-6050 (I2C), драйвер TB6612FNG
- Моторы JGA25-370 6 В 210 об/мин с энкодерами. По замеру рулеткой ~285 импульсов
  на оборот колеса (0.69 мм на импульс; паспортные 45:1 и 495 не подтвердились), колёса 63 мм
- Аккумулятор 2S Li-ion (7.4 В)
- Bluetooth HC-05 на аппаратном UART D0/D1, 115200 бод

Распиновка (снята прозвонкой; `docs/schema-outdated.png` плате **не
соответствует**):

| Nano | Куда |
|---|---|
| D9 / D7 / D8 | TB6612 PWMA / AIN1 / AIN2 — левое колесо |
| D10 / D5 / D4 | TB6612 PWMB / BIN1 / BIN2 — правое колесо |
| D6 | TB6612 STBY |
| A4 / A5 | MPU-6050 SDA / SCL |
| D2 / A2 | энкодер левого, каналы A / B |
| D3 / A3 | энкодер правого, каналы A / B |
| D0 / D1 | HC-05 TX / RX (RX через делитель 1к/2к) |

## Установка на ПК (один раз)

Для езды нужен только **Python 3** (на Windows — с python.org, галочка «Add to
PATH»). Пакеты `pygame` и `pyserial`:

- **Windows, macOS** — клиент при первом запуске поставит сам; если система не
  даёт ставить пакеты глобально (Homebrew-Python), создаст своё окружение
  `tools/.venv` и дальше будет запускаться из него.
- **Linux** — клиент ничего не ставит: покажет команду для твоего дистрибутива
  (например, `sudo apt install python3-pygame python3-serial`) и будет ждать,
  пока пакеты не появятся.

Дальше спарить HC-05. **PIN (пароль) для подключения: `1234`.**

- **Windows** — «Параметры → Bluetooth → Добавить устройство». Появятся два
  COM-порта, клиент сам выберет исходящий.
- **macOS** — «Системные настройки → Bluetooth». Порт появится как
  `/dev/cu.HC-05…` (или `/dev/cu.<имя модуля>`), клиент найдёт его сам.
- **Linux** — спарить (`bluetoothctl`: `scan on`, `pair <MAC>`, `trust <MAC>`),
  затем привязать последовательный порт: `sudo rfcomm bind 0 <MAC>` — появится
  `/dev/rfcomm0`. Пользователь должен быть в группе `dialout`
  (`sudo usermod -aG dialout $USER`, перелогиниться).

Если автопоиск не справился — указать порт вручную:
`wasd.bat --port COM13`, `./wasd.sh --port /dev/rfcomm0`.

Для **прошивки** нужен [arduino-cli](https://arduino.github.io/arduino-cli/)
и ядро `arduino-cli core install arduino:avr`. `flash.bat` рассчитан на Windows
(arduino-cli в `%LOCALAPPDATA%\arduino-cli\`); на других ОС — та же команда
вручную: `arduino-cli compile --upload -p <порт> -b arduino:avr:nano firmware/gyrobot_tumbller`.

## Прошивка

Прошивка хранится в роботе и после выключения не пропадает, так что для
обычной езды `flash.bat` не нужен. Он нужен, когда:
- поменял значения параметров в начале `gyrobot_tumbller.ino` (то, что
  выставлено по Bluetooth, живёт только до перезагрузки);
- появилась новая версия прошивки;
- в плате оказалась другая прошивка и нужно вернуть рабочую.

1. **Вынуть HC-05 из разъёма** — его TX на D0 мешает загрузчику
   (ошибка `not in sync`).
2. Подключить USB (у нас COM10; проверить: `arduino-cli board list`).
3. Двойной клик по **`flash.bat`** (другой порт: `flash.bat COM5`).
4. Вставить HC-05 обратно, дальше — «Быстрый старт».

## Настройка на лету

Все коэффициенты меняются по Bluetooth без перепрошивки. Чтобы подобранное
пережило выключение — команда **`save`** (запись в память робота); **`defaults`** —
вернуть заводские значения прошивки и очистить память. При старте робот пишет,
откуда взял настройки. Если прошивку обновили и заводские значения в ней
поменялись, старые сохранённые не применяются — берутся новые заводские.

```
python tools/talk.py --cmds "p"            # показать все параметры
python tools/talk.py --cmds "kd 0.45;p"    # поменять и показать
python tools/talk.py --cmds "save"         # сохранить насовсем
```

Клиент WASD при этом должен быть закрыт: порт один. Открытие COM13 плату не
перезагружает, открытие USB-порта — перезагружает (параметры сбросятся).

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `kp`, `kd` | 20, 0.5 | баланс: ШИМ на градус наклона и на °/с |
| `ksp`, `ksi` | 8, 0.25 | скорость и память положения колёс |
| `az` | −10.5 | ноль угла (точка равновесия); подобран с камерой, без неё −2.8 |
| `dba`, `dbb` | 6, 4 | добавка ШИМ на мёртвую зону левого / правого мотора |
| `move` | 15 | скорость езды (1 ≈ 17 мм/с, 15 ≈ 26 см/с) |
| `acc`, `dec` | 0.7, 0.45 | плавность разгона / торможения |
| `bleed` | 20 | как быстро робот «забывает» разгон после отпускания W/S |
| `ymax` | 90 | скорость поворота, °/с |
| `kt`, `tff`, `kh` | 0.5, 0.3, 1.0 | поворот: демпфер, прямая подача, удержание курса |
| `kw`, `kwi`, `fla`, `pks` | 4, 0.5, 10, 3 | поворот на месте: П и И по колёсам, трение левого, демпфер |
| `fall` | 30 | угол, после которого моторы отключаются |
| `knt`, `knd` | 2, 0.3 | возврат домой: скорость доворота на градус ошибки, замедление на подходе |
| `ntol`, `ftol` | 5, 2 | возврат домой: «дома» ближе N см; доворот в исходный курс до N° |
| `bw` | 60 | за мячом: размер мяча в кадре (пикс) на нужной дистанции — больше значит ближе |
| `kbd`, `bmax` | 10, 8 | за мячом: резвость подъезда и потолок скорости |

Служебные команды: `p` — параметры, `tele 0` / `tele 1` — выкл/вкл телеметрию, `z` — принять
текущий угол за ноль, `t 60` — прогнать моторы 1 с (робот лежит; оба счётчика
должны вырасти в плюс).

## Карта и возврат домой

Справа в окне клиента — карта: синий след, робот зелёной стрелкой, дом жёлтым
крестиком, клетка 10 см. Робот сам считает, где он: путь по энкодерам колёс,
направление по гироскопу.

**Дом** ставится сам, когда робот встаёт (взводится), и кнопкой **R**. Жми R,
когда робот уже стоит, — пока он катится, точка «уезжает».

**H** — робот разворачивается к дому, едет по прямой, останавливается и
доворачивается как стоял при R. Любая из W/A/S/D сразу отменяет возврат и
отдаёт управление тебе. Препятствия робот не объезжает — датчиков нет.

Точность: после одной поездки с поворотами — 2–5 см до точки старта. Ошибка
одометрии копится: после нескольких поездок без R промах растёт — перед новой
серией жми R.

## Видео с камеры

Если на роботе стоит камера OpenMV с WiFi-шилдом и на ней запущена программа
`tools/openmv/main_ball.py` (скопировать на диск камеры как `main.py`; сеть — в
`wifi_config.py` на камере, образец рядом), клиент показывает видео прямо в
окне, под клавишами.
Камеру он находит в локальной сети сам и запоминает адрес; вручную —
`wasd.bat --cam 192.168.1.132`, без видео — `--no-cam`.

- Компьютер должен быть в той же сети, что и камера (она умеет только 2.4 ГГц).
- Камера отдаёт поток одному зрителю: пока видео показывает клиент, в браузере
  (`http://<ip камеры>/`) оно не откроется, и наоборот.
- Светодиод камеры: синий — сети нет, зелёный — сеть есть, красный — сбой
  (камера сама перезагрузится, причина — в `last_error.txt` на её диске).
- OpenMV IDE с работающей программой не дружит: чтобы подключиться в IDE,
  переименуй `main.py` на диске камеры.

## За красным мячом

**F** — робот едет за красным мячом: поворачивается, чтобы мяч был по центру
кадра, и держит дистанцию — подъезжает, если мяч далеко, отъезжает, если
близко. Мяча не видно — стоит и ждёт. Ещё раз **F** или любая из W/A/S/D —
выключить. В окне клиента: «за мячом: вижу / не вижу», на видео мяч в зелёной
рамке.

Мяч ищет сама камера (по цвету, 20+ раз в секунду) и сообщает роботу по
проводу, где он в кадре; Wi-Fi и клиент для этого не нужны — только чтобы
включить режим и смотреть.

- Дистанция — параметр `bw`: какого размера (в пикселях кадра 320×240) должен
  быть мяч. Текущий размер виден в окне клиента: поставь мяч как надо и
  впиши это число (`bw 75`, потом `save`).
- Цвет подстраивается без проводов: поставь мяч в центр кадра, открой
  `http://<ip камеры>/color` — там цвет центра в LAB и текущий порог. Новый
  порог: `http://<ip камеры>/thr?v=Lmin,Lmax,Amin,Amax,Bmin,Bmax` — камера его
  запомнит. Красный — это большой A (у нашего мяча 34…45, у стола и стен до 20).
- Диапазонов цвета два: первый — мяч на свету, второй — тот же мяч в тени (он
  тусклее: яркость 10–30, A 18–36). Второй задаётся так же, через `/thr2?v=...`,
  выключается `/thr2?v=off`. Один общий широкий диапазон ловил бы и освещённую
  кожу с деревом, поэтому их два.
- Страницы камеры открываются, только когда видео никто не смотрит: клиент WASD
  закрыт или запущен с `--no-cam`, вкладка с видео в браузере закрыта.
- Робот едет на самое крупное красное пятно: красная одежда в кадре его обманет.

## Если что-то не так

| Симптом | Причина / что делать |
|---|---|
| Колёса не дёрнулись, робот не встаёт | калибровка ещё идёт или робота шевелят — положить и подождать |
| Стоит с наклоном, крутится на месте | сбилась калибровка гироскопа — положить робота на 5 с, она пересчитается |
| Клиент пишет «Робот не найден» | клиент пишет причину по каждому порту. «Занят» — к роботу подключён другой компьютер/телефон или `talk.py`; если никого нет — выключить и включить робота. «Не отвечает» — робот выключен или не тот порт. На Linux — не сделан `rfcomm bind` |
| Клиент закрыли нештатно (закрыли Терминал) | при следующем запуске клиент сам найдёт и закроет повисший прошлый экземпляр |
| Окно открыто, но робот не едет | окно не в фокусе — кликнуть по нему; «нет данных от робота» — связь пропала, клиент переподключится сам |
| Заливка: `not in sync` | не вынут HC-05 |
| COM10 «висит» (ошибка 5) | передёрнуть USB-кабель |
| Трясётся стоя сильнее обычного | проверить заряд аккумулятора, крепление MPU |

## Структура

```
wasd.bat / .sh / .command  — клиент WASD для Windows / Linux / macOS
flash.bat                  — прошивка (Windows)
firmware/gyrobot_tumbller/ — прошивка робота
tools/wasd.py              — клиент WASD: окно pygame, карта, автопоиск порта, ставит пакеты (Linux — просит), лог в tools/logs/
tools/wasdmap.py           — логика карты (поза из телеметрии, след, масштаб) + test_wasdmap.py
tools/wasdcam.py           — видео с камеры (поиск в сети, разбор MJPEG) + test_wasdcam.py
tools/openmv/              — программы для камеры OpenMV: поиск мяча + видео, тесты связи
tools/talk.py              — команды и чтение телеметрии
tools/turnstat.py,
tools/stopstat.py          — разбор логов поворотов и остановок
tools/hc05_at_bridge/      — разовая перенастройка HC-05 на 115200
docs/STATUS.md             — подробный журнал: как всё искали и настраивали
docs/sessions/             — контекст рабочих сессий
docs/research/             — исследование проверенных проектов
```
